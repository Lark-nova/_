Getting Started

Understand the platform before you write code.

What is LARK?

LARK builds intelligence systems for developers and organizations. The platform exposes models, APIs, and tooling so you can add reasoning, generation, and tool use to products without running training infrastructure yourself.

What is Nova AI?

Nova is LARK’s model family. Different Nova models trade off depth of reasoning, latency, and cost. You select a model per request; the API surface stays the same.

  • Nova Apex — frontier reasoning for complex work
  • Nova Hyper — high throughput for production scale
  • Nova Pro — balanced quality for everyday workloads

How the platform works

Your application sends a request (messages, model, options) to the LARK API using an API key. The model consumes tokens (pieces of text) as input and produces tokens as output within a context window. You receive a structured response, optionally streamed token-by-token.

Mental model: Client → API key → Model → Tokens in / tokens out → Response (or stream).

Models

A model is a trained system that maps prompts to completions. Model choice affects quality, speed, and price.

API

HTTPS endpoints and official SDKs. Most apps use the Chat Completions-style interface.

Tokens

Text is split into tokens for billing and context accounting. Roughly: 1 token ≈ 4 characters of English, but this varies by language and content.

Requests & responses

A request includes the model id, a list of messages, and optional parameters (temperature, max tokens, tools). The response includes the assistant message, usage counts, and metadata.

Context windows

The maximum tokens the model can consider at once (input + output). Exceeding the window causes errors or truncation—design prompts and retrieval so critical information fits.

Quickstart

Go from zero to a successful API response in a few minutes.

Create an API key

Open the API Keys console, create a key, and store it as an environment variable. Never commit keys to git or ship them in frontend code.

# macOS / Linux
export LARK_API_KEY="lark_sk_..."

Install an SDK

# Python
pip install lark

# Node.js
npm install @lark/sdk

Make your first request

Python

from lark import Lark

client = Lark()  # reads LARK_API_KEY

response = client.chat.create(
    model="nova-pro",
    messages=[
        {"role": "user", "content": "Explain tokens in one sentence."}
    ],
)

print(response.choices[0].message.content)

JavaScript

import Lark from "@lark/sdk";

const client = new Lark();

const response = await client.chat.create({
  model: "nova-pro",
  messages: [{ role: "user", content: "Explain tokens in one sentence." }],
});

console.log(response.choices[0].message.content);

Expected response shape

{
  "id": "chatcmpl_...",
  "model": "nova-pro",
  "choices": [
    {
      "index": 0,
      "message": {
        "role": "assistant",
        "content": "Tokens are the small text units models read and generate."
      },
      "finish_reason": "stop"
    }
  ],
  "usage": {
    "prompt_tokens": 12,
    "completion_tokens": 18,
    "total_tokens": 30
  }
}

Common mistakes

  • Missing or invalid LARK_API_KEY
  • Calling the API from browser JavaScript with a secret key
  • Wrong model id (typos like nova_pro instead of nova-pro)
  • Empty messages array

Core Concepts

Shared vocabulary for the rest of the docs.

What is a model?

A model is a function from input tokens to output tokens, trained to follow instructions and continue text usefully. LARK hosts models; you choose which one handles each request.

What is context?

Context is everything the model can “see” for a request: system instructions, prior messages, retrieved documents, and tool results. Better context usually matters more than clever wording alone.

What are tokens?

Tokens are subword units. Billing and rate limits are token-based. Long documents and code consume many tokens—use retrieval or summarization when inputs are large.

What is reasoning?

Reasoning models spend more internal computation on multi-step problems (planning, math, analysis). Apex is optimized for this; Hyper prioritizes speed for simpler or high-volume tasks.

What is streaming?

Streaming delivers partial tokens as they are generated so UIs can show progress instead of waiting for the full completion.

What is tool calling?

You describe tools (functions) with JSON schemas. The model may return a structured call; your code runs the tool and can send results back for a final answer.

What are structured outputs?

You constrain the model to return JSON that matches a schema—useful for forms, pipelines, and type-safe integrations.

Models

Pick the smallest model that meets quality needs; upgrade when evaluation says you must.

Nova Apex

Frontier reasoning model for complex analysis, long-context understanding, and high-stakes workflows.

  • Best for: research, planning, multi-step analysis
  • Strengths: depth, instruction following, hard problems
  • Limitations: higher latency and cost than Hyper/Pro
  • Latency profile: standard (quality over speed)

Nova Hyper

Fast production model optimized for throughput and efficiency.

  • Best for: agents, automation, high QPS features
  • Strengths: low latency, cost efficiency at scale
  • Limitations: less depth than Apex on the hardest tasks
  • Latency profile: fast

Nova Pro

Balanced model for general product use.

  • Best for: chat, coding assistance, content, everyday workflows
  • Strengths: strong quality/speed balance
  • Limitations: not the peak of either frontier depth or raw speed

nova-proStrongFastGeneral workloads

Exact context limits and pricing are published in the platform console and may change; always read the current model card in the dashboard.

Authentication

Every request must present a valid API key.

API keys

Keys are secrets issued per organization. Create and revoke them in the API Keys console. Prefer separate keys for development and production.

Environment variables

# .env (never commit)
LARK_API_KEY=lark_sk_...

# Python
import os
from lark import Lark
client = Lark(api_key=os.environ["LARK_API_KEY"])

# Node.js
import Lark from "@lark/sdk";
const client = new Lark({ apiKey: process.env.LARK_API_KEY });
Never put secret keys in mobile apps, browser bundles, public repos, or client-side analytics. Use a backend or edge function as a proxy.

Security practices

  • Rotate keys on a schedule and after staff changes
  • Scope production keys tightly; use read-only where possible
  • Monitor usage for spikes that suggest leakage
  • Revoke immediately if a key is exposed

Chat Completions API

The primary interface for conversational and instruction-following workloads.

Endpoint

POST /v1/chat/completions

Request format

{
  "model": "nova-pro",
  "messages": [
    { "role": "system", "content": "You are a precise technical assistant." },
    { "role": "user", "content": "Summarize rate limits in 3 bullets." }
  ],
  "temperature": 0.2,
  "max_tokens": 500
}

Parameters

ParameterDescription
modelModel id, e.g. nova-apex
messagesOrdered list of role/content objects
temperatureRandomness (lower = more deterministic)
max_tokensCap on generated tokens
streamIf true, SSE token stream
toolsOptional tool definitions for function calling

System vs user messages

Use system for durable instructions (persona, format, safety). Use user for the current task. Use assistant for prior model turns in multi-turn chat.

Response schema

Successful responses include choices[].message, finish_reason, and usage. Handle non-200 responses using the error object described in Errors.

Best practices

  • Keep system prompts stable; put volatile data in user messages
  • Set low temperature for extraction and classification
  • Always set sensible max_tokens for cost control
  • Log request ids for support and debugging

Streaming

Stream tokens for responsive UIs and early cancellation.

With stream: true, the API sends server-sent events. Each event carries a partial delta of the assistant message. Concatenate deltas until finish_reason appears.

# Python (sketch)
stream = client.chat.create(model="nova-hyper", messages=messages, stream=True)
for event in stream:
    delta = event.choices[0].delta.content or ""
    print(delta, end="")
// JavaScript (sketch)
const stream = await client.chat.create({ model: "nova-hyper", messages, stream: true });
for await (const event of stream) {
  process.stdout.write(event.choices[0]?.delta?.content ?? "");
}

Streaming does not reduce total tokens; it changes delivery. Implement client-side abort when users cancel generation.

Vision

Send images alongside text for multimodal understanding.

Supported inputs typically include common formats such as PNG, JPEG, and WebP (see console for current limits on size and resolution). Use cases: document screenshots, UI debugging, chart reading, product photos.

Pass image content as part of a user message (URL or base64, depending on API version). Pair images with clear instructions: what to extract, what to ignore, and the output format you need.

Vision increases token usage. Prefer cropped regions over full high-resolution pages when possible.

Voice

Speech-oriented workflows on top of Nova.

  • Speech-to-text — transcribe audio for chat or search
  • Text-to-speech — speak assistant replies
  • Realtime — low-latency conversational loops

Design for imperfect transcripts: confirm critical fields, and keep tools idempotent. For production, stream partial transcripts and handle barge-in (user interruption).

Function Calling

Let the model request tools; your code executes them.

Why tools exist

Models should not invent live data. Tools give grounded access to weather, databases, search, ticketing systems, and internal APIs.

Flow

  1. You send tool schemas with the chat request
  2. Model may return a tool call (name + arguments)
  3. Your server runs the tool
  4. You send tool results back as messages
  5. Model produces a final natural-language (or structured) answer

Schema design

Keep tools small and explicit. Name arguments clearly. Validate arguments before execution. Example domains: weather lookup, SQL read query, document search.

Never expose destructive tools without authorization checks and audit logs.

Structured Outputs

Get JSON that matches a schema for reliable automation.

Structured outputs reduce brittle regex parsing. Define the schema your app expects (fields, types, enums). Validate on the server even when the API enforces schema. Use for classifications, extraction, and multi-field forms.

Agents

Agents plan, call tools, and iterate toward a goal.

An agent loop typically: plan → act (tool) → observe → update plan → stop when done or budget exhausted. Add memory carefully (summaries, not unbounded transcripts). Production agents need timeouts, max steps, human approval for sensitive actions, and full traces for debugging.

Prompt Engineering

Clear instructions outperform clever tricks.

  • System prompts — role, tone, hard constraints, output format
  • Instructions — task steps; prefer numbered procedures
  • Context — only relevant retrieved facts; cite sources when needed
  • Reasoning — ask for stepwise work on hard problems; verify final answers

Common mistakes

  • Contradictory instructions
  • Huge irrelevant context
  • No success criteria (“write something good”)
  • Asking for confidential data the model should not invent

Rate Limits

Protect the platform and your budget.

Limits may apply to requests per minute (RPM) and tokens per minute (TPM). When limited, back off with jittered exponential retry. Cache identical prompts where safe. Batch offline jobs. Request limit increases with clear production traffic patterns.

Errors

ClassTypical causeWhat to do

Always log status, error code, and request id. See Status during incidents.

Security

  • Server-side keys only
  • Least-privilege keys and network controls
  • Do not send unnecessary PII in prompts
  • Review retention settings for your plan
  • Treat model output as untrusted in security-sensitive flows

SDKs

Python and JavaScript/TypeScript are the primary official SDKs. Install from the public package registries, configure via LARK_API_KEY, and prefer the chat interface for most apps. Additional language SDKs may appear on the platform roadmap; HTTP remains the stable contract underneath.

Cookbook

Patterns you can adapt.

  • Chatbot — system prompt + short memory window + safety refusals
  • Research assistant — retrieve → cite → summarize with Apex
  • Coding assistant — repo context packs + Hyper for iteration speed
  • Document analysis — chunk, embed/search, then answer with sources
  • Customer support — policy retrieval + escalation tool
  • Knowledge base — strict grounded mode when unsure
  • Enterprise automation — structured outputs + approval gates

FAQ

Can I use Nova in the browser?

Call LARK from your backend. Browsers should never hold secret API keys.

Which model should I start with?

Start with nova-pro. Move hard tasks to Apex; move high-QPS paths to Hyper after measuring.

How is usage billed?

Primarily by tokens processed (input and output). Check the console for current rates.

Is streaming required?

No. Use streaming for UX; non-streaming is fine for batch jobs.
